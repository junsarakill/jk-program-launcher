# Steam UAC 및 Overlay 권한 문제 트러블슈팅

## 1. 문제 발생 배경

일부 게임은 정상적인 실행 및 기능 사용을 위해 관리자 권한이 필요하다.

그런데 게임이 관리자 권한으로 실행되고 Steam은 일반 권한으로 실행되는 경우, 권한 수준(Integrity Level)의 차이로 인해 Steam Overlay가 게임 프로세스에 정상적으로 주입되지 않는 문제가 발생할 수 있다.

이를 해결하기 위해 Steam 자체도 관리자 권한으로 실행하도록 설정했다.

- Steam 실행 파일의 호환성 설정에서 `관리자 권한으로 이 프로그램 실행` 활성화
- 모든 사용자에 대한 설정에도 동일하게 적용
- Steam과 게임의 권한 수준을 일치시켜 Overlay 정상 작동 유도

## 2. 문제 발생

Steam을 관리자 권한으로 실행하도록 설정한 이후, Steam을 실행하거나 게임 실행 요청을 전달할 때마다 UAC 확인 창이 표시되는 문제가 발생했다.

기존에는 별다른 확인 절차 없이 게임을 실행할 수 있었지만, 이제는 실행할 때마다 관리자 권한 허용을 위해 동일한 클릭을 반복해야 했다.

기능적인 문제뿐 아니라 일상적인 사용 과정에서 불필요한 사용자 확인을 반복하게 되는 UX 문제가 발생한 것이다.

특히 이미 Steam이 관리자 권한으로 실행 중이고 프로세스도 중복되지 않은 상황에서 외부 실행 요청만으로 UAC가 다시 표시되는 점이 불편했다.

### 시도한 실행 방식

Steam URI를 이용한 게임 실행:

```text
steam://rungameid/3308670
```

AHK v2에서 Steam 실행 파일을 직접 호출하는 방식도 시도했다.

```ahk
Run('"C:/경로/스팀.exe" -- "steam://rungameid/3308670"')
```

그러나 실행 방식을 변경해도 UAC가 표시되는 현상은 해결되지 않았다.

## 3. 해결 방법 검토

### 3.1 작업 스케줄러를 이용한 UAC 예외 처리

기존에 알고 있던 Windows 작업 스케줄러의 최고 권한 실행 기능을 활용하는 방법을 검토했다.

작업 스케줄러에 특정 프로그램 실행 작업을 등록하고 `가장 높은 수준의 권한으로 실행`을 활성화하면, 해당 작업을 실행할 때 일반적인 UAC 확인 절차 없이 관리자 권한으로 실행할 수 있다.

이를 이용하면 반복적인 UAC 확인 문제를 해결할 수 있을 것으로 판단했다.

다만 기존 실행 구조에서 문제가 발생할 수 있었다.

현재 실행 구조는 다음과 같다.

- AHK 실행 스크립트: 일반 권한
- Steam: 일반 권한으로 실행 요청
- 게임: 일반 권한으로 실행 요청

여기서 작업 스케줄러를 통해 Steam과 게임만 관리자 권한으로 실행하도록 변경하면, 일반 권한으로 실행 중인 기존 AHK 스크립트와 권한 수준이 달라진다.

결국 기존 실행 스크립트에서 관리자 권한 실행을 요청하는 과정에서 UAC가 다시 발생할 가능성이 있었다.

즉, 작업 스케줄러를 이용한 예외 처리 자체는 적절하지만, 기존 실행 스크립트에서 해당 작업을 직접 호출하는 구조만으로는 원하는 결과를 얻지 못할 수 있었다.

### 3.2 기존 실행 스크립트까지 관리자 권한 적용

문제를 단순하게 해결하려면 기존 AHK 실행 스크립트 자체를 관리자 권한으로 실행하도록 변경할 수도 있다.

그러나 이는 과도한 해결책이라고 판단했다.

기존 실행 스크립트는 프로그램의 실행 정보를 받아 실제 실행을 담당하는 공통 유틸리티 성격을 가진다.

또한 해당 실행 스크립트를 상속받아 그룹 단위로 실행을 관리하는 하위 스크립트도 존재한다.

특정 게임 하나의 문제 때문에 전체 실행 환경을 관리자 권한으로 변경하는 것은 기존 구조와 사용 목적에 적합하지 않았다.

### 3.3 별도 관리자 프로세스를 통한 실행 검토

기존 실행 스크립트는 일반 권한으로 유지하면서, 별도의 관리자 권한 프로세스에서 특정 실행 함수를 호출하는 방법도 검토했다.

구상한 구조는 다음과 같다.

1. 기존 AHK 스크립트는 일반 권한으로 실행한다.
2. 관리자 권한으로 실행되는 별도 프로세스를 작업 스케줄러에 등록한다.
3. 기존 스크립트에서 관리자 권한 실행이 필요하다고 판단하면 별도 프로세스에 실행 정보를 전달한다.
4. 별도 프로세스가 전달받은 정보를 이용해 기존 실행 함수를 호출한다.

이 방식이라면 기존 실행 스크립트의 권한을 변경하지 않고도 관리자 권한 실행을 분리할 수 있다.

다만 서로 다른 프로세스에서 특정 함수를 실행하려면 별도의 프로세스 간 통신이 필요하다.

Named Pipe, 임시 JSON 파일, 명령 전달 및 응답 처리 등의 구현이 추가되어야 한다.

방향성 자체는 적절했지만, 특정 게임 하나의 실행 문제를 해결하기 위해 추가해야 하는 구조와 코드가 지나치게 많다고 판단했다.

## 4. 최종 결정: 해당 게임 전용 작업 스케줄러 등록

여러 해결 방법을 비교한 결과, 문제가 발생하는 특정 게임을 Steam으로 실행하는 작업 자체를 작업 스케줄러에 별도로 등록하는 방식으로 결정했다.

기존 AHK 실행 스크립트의 권한이나 구조는 변경하지 않는다.

대신 해당 게임에 한해서 작업 스케줄러를 통해 Steam 실행을 요청하도록 처리한다.

### 작업 스케줄러 설정 예시

| 항목 | 설정 |
|---|---|
| 작업 이름 | `JK_Steam_Game_3308670` |
| 프로그램 | `C:/경로/스팀.exe` |
| 실행 인수 | `-applaunch 3308670` |
| 실행 계정 | 현재 사용자 |
| 가장 높은 수준의 권한으로 실행 | 활성화 |

이렇게 등록한 작업은 해당 게임 실행 전용으로 사용한다.

## 5. 결론

이번 문제의 핵심은 관리자 권한이 필요한 게임에서 Steam Overlay를 정상적으로 사용하기 위해 Steam도 관리자 권한으로 실행해야 했고, 그 결과 Steam 실행 요청마다 UAC 확인이 반복되어 일상적인 사용성이 저하되었다는 점이다.

이를 해결하기 위해 작업 스케줄러를 통한 UAC 예외 처리를 검토했지만, 기존 AHK 실행 스크립트가 일반 권한으로 동작하기 때문에 단순히 Steam과 게임만 관리자 권한으로 실행하는 방식에는 한계가 있었다.

기존 실행 스크립트까지 관리자 권한으로 변경하는 방법은 적용 범위가 지나치게 넓었고, 별도 관리자 프로세스와 IPC를 이용하는 방법은 특정 게임 하나의 문제를 해결하기에는 구현 복잡도가 높았다.

따라서 기존 실행 시스템은 그대로 유지하면서 **문제가 발생하는 해당 게임의 Steam 실행 작업만 작업 스케줄러에 UAC 예외로 등록하는 방식**을 최종 해결 방향으로 결정했다.

최소한의 변경으로 특정 문제만 분리해서 처리하는 것이 현재 실행 스크립트의 구조와 유지보수 측면에서 가장 적절하다고 판단했다.

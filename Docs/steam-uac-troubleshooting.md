# Steam UAC 및 Overlay 권한 문제 트러블슈팅

## 1. 문제 발생 배경

일부 게임은 정상적인 실행 및 기능 사용을 위해 관리자 권한이 필요하다.

그런데 게임이 관리자 권한으로 실행되고 Steam은 일반 권한으로 실행되는 경우, 권한 수준(Integrity Level)의 차이로 인해 Steam Overlay가 게임 프로세스에 정상적으로 주입되지 않는 문제가 발생할 수 있다.

이를 해결하기 위해 Steam 자체도 관리자 권한으로 실행하도록 설정했다.

- Steam 실행 파일의 호환성 설정에서 `관리자 권한으로 이 프로그램 실행` 활성화
- 모든 사용자에 대한 설정에도 동일하게 적용
- Steam과 게임의 권한 수준을 일치시켜 Overlay 정상 작동 유도

## 2. 문제 발생

Steam을 관리자 권한으로 실행하도록 설정한 이후, Steam을 실행하거나 게임 실행 요청을 전달할 때마다 UAC 확인 창이 표시되는 문제가 발생했다.

기존에는 별다른 확인 절차 없이 게임을 실행할 수 있었지만, 이제는 실행할 때마다 관리자 권한 허용을 위해 동일한 클릭을 반복해야 했다.

기능적인 문제뿐 아니라 일상적인 사용 과정에서 불필요한 사용자 확인을 반복하게 되는 UX 문제가 발생한 것이다.

특히 이미 Steam이 관리자 권한으로 실행 중이고 프로세스도 중복되지 않은 상황에서 외부 실행 요청만으로 UAC가 다시 표시되는 점이 불편했다.

### 시도한 실행 방식

Steam URI를 이용한 게임 실행:

```text
steam://rungameid/3308670
```

AHK v2에서 Steam 실행 파일을 직접 호출하는 방식도 시도했다.

```ahk
Run('"C:/경로/스팀.exe" -- "steam://rungameid/3308670"')
```

그러나 실행 방식을 변경해도 UAC가 표시되는 현상은 해결되지 않았다.

## 3. 해결 방법 검토

### 3.1 작업 스케줄러를 이용한 UAC 예외 처리

기존에 알고 있던 Windows 작업 스케줄러의 최고 권한 실행 기능을 활용하는 방법을 검토했다.

작업 스케줄러에 특정 프로그램 실행 작업을 등록하고 `가장 높은 수준의 권한으로 실행`을 활성화하면, 해당 작업을 실행할 때 일반적인 UAC 확인 절차 없이 관리자 권한으로 실행할 수 있다.

이를 이용하면 반복적인 UAC 확인 문제를 해결할 수 있을 것으로 판단했다.

다만 기존 실행 구조에서 문제가 발생할 수 있었다.

현재 실행 구조는 다음과 같다.

- AHK 실행 스크립트: 일반 권한
- Steam: 일반 권한으로 실행 요청
- 게임: 일반 권한으로 실행 요청

여기서 작업 스케줄러를 통해 Steam과 게임만 관리자 권한으로 실행하도록 변경하면, 일반 권한으로 실행 중인 기존 AHK 스크립트와 권한 수준이 달라진다.

결국 기존 실행 스크립트에서 관리자 권한 실행을 요청하는 과정에서 UAC가 다시 발생할 가능성이 있었다.

즉, 작업 스케줄러를 이용한 예외 처리 자체는 적절하지만, 기존 실행 스크립트에서 해당 작업을 직접 호출하는 구조만으로는 원하는 결과를 얻지 못할 수 있었다.

### 3.2 기존 실행 스크립트까지 관리자 권한 적용

문제를 단순하게 해결하려면 기존 AHK 실행 스크립트 자체를 관리자 권한으로 실행하도록 변경할 수도 있다.

그러나 이는 과도한 해결책이라고 판단했다.

기존 실행 스크립트는 프로그램의 실행 정보를 받아 실제 실행을 담당하는 공통 유틸리티 성격을 가진다.

또한 해당 실행 스크립트를 상속받아 그룹 단위로 실행을 관리하는 하위 스크립트도 존재한다.

특정 게임 하나의 문제 때문에 전체 실행 환경을 관리자 권한으로 변경하는 것은 기존 구조와 사용 목적에 적합하지 않았다.

### 3.3 별도 관리자 프로세스를 통한 실행 검토

기존 실행 스크립트는 일반 권한으로 유지하면서, 별도의 관리자 권한 프로세스에서 특정 실행 함수를 호출하는 방법도 검토했다.

구상한 구조는 다음과 같다.

1. 기존 AHK 스크립트는 일반 권한으로 실행한다.
2. 관리자 권한으로 실행되는 별도 프로세스를 작업 스케줄러에 등록한다.
3. 기존 스크립트에서 관리자 권한 실행이 필요하다고 판단하면 별도 프로세스에 실행 정보를 전달한다.
4. 별도 프로세스가 전달받은 정보를 이용해 기존 실행 함수를 호출한다.

이 방식이라면 기존 실행 스크립트의 권한을 변경하지 않고도 관리자 권한 실행을 분리할 수 있다.

다만 서로 다른 프로세스에서 특정 함수를 실행하려면 별도의 프로세스 간 통신이 필요하다.

Named Pipe, 임시 JSON 파일, 명령 전달 및 응답 처리 등의 구현이 추가되어야 한다.

방향성 자체는 적절했지만, 특정 게임 하나의 실행 문제를 해결하기 위해 추가해야 하는 구조와 코드가 지나치게 많다고 판단했다.

## 4. 당시의 해결 방향: 해당 게임 전용 작업 스케줄러 등록

여러 해결 방법을 비교한 결과, 문제가 발생하는 특정 게임을 Steam으로 실행하는 작업 자체를 작업 스케줄러에 별도로 등록하는 방식으로 결정했다.

기존 AHK 실행 스크립트의 권한이나 구조는 변경하지 않는다.

대신 해당 게임에 한해서 작업 스케줄러를 통해 Steam 실행을 요청하도록 처리한다.

### 작업 스케줄러 설정 예시

| 항목 | 설정 |
|---|---|
| 작업 이름 | `JK_Steam_Game_3308670` |
| 프로그램 | `C:/경로/스팀.exe` |
| 실행 인수 | `-applaunch 3308670` |
| 실행 계정 | 현재 사용자 |
| 가장 높은 수준의 권한으로 실행 | 활성화 |

이렇게 등록한 작업은 해당 게임 실행 전용으로 사용한다.

### 당시 구현 방식

작업 스케줄러에 등록한 작업을 실행하는 `.lnk` 바로가기를 별도로 생성하고, 기존 실행 시스템에서는 해당 바로가기의 경로를 실행하도록 구성했다.

따라서 기존 AHK 실행 코드 자체는 변경하지 않았다.

## 5. 당시의 결론

당시에는 기존 실행 시스템은 그대로 유지하면서 **문제가 발생하는 해당 게임의 Steam 실행 작업만 작업 스케줄러에 UAC 예외로 등록하는 방식**을 최종 해결 방향으로 결정했다.

최소한의 변경으로 특정 문제만 분리해서 처리하는 것이 현재 실행 스크립트의 구조와 유지보수 측면에서 가장 적절하다고 판단했다.

다만 이후 다른 Steam 게임에서도 동일한 UAC 문제가 발생할 수 있다는 점을 확인하면서, 게임마다 작업 스케줄러 작업을 등록하는 방식이 장기적으로 적절한지 재검토하게 되었다.

## 6. 추가 조사 및 최종 해결: Steam 호환성 관리자 권한 설정 해제

이후 다른 Steam 게임을 기존 실행 스크립트로 실행하는 과정에서도 동일한 UAC 문제가 발생하는 것을 확인했다.

개별 게임마다 작업 스케줄러 작업을 등록하는 방식으로 대응할 수는 있었지만, Steam 게임이 늘어날수록 예외 작업과 바로가기 파일도 함께 증가하게 된다.

이는 특정 게임 하나의 문제가 아니라 Steam의 실행 환경 자체를 다시 살펴볼 필요가 있음을 의미했다.

### 6.1 실행 경로에 따른 차이 확인

추가 조사 과정에서 Steam이 이미 관리자 권한으로 실행 중인 상태에서도 게임 실행 요청을 전달하는 방식에 따라 UAC 발생 여부가 달라진다는 점을 확인했다.

| 실행 방식 | UAC 발생 | 실행된 게임의 권한 |
|---|---|---|
| 관리자 권한 Steam 클라이언트 내부에서 게임 실행 | 없음 | 관리자 권한 |
| `steam://rungameid/3308670` URI 호출 | 발생 | 관리자 권한 |
| Steam.exe에 `--applaunch` 인수를 전달하여 실행 | 발생 | 관리자 권한 |

특히 백그라운드 Steam 프로세스의 존재 여부와 관계없이 외부에서 URI 또는 실행 파일을 통해 게임 실행을 요청하면 UAC가 표시되는 현상이 관찰되었다.

이를 통해 단순히 Steam이 실행 중인지 여부만으로는 문제를 설명할 수 없으며, Steam 실행 파일의 호환성 설정도 함께 확인할 필요가 있다고 판단했다.

### 6.2 호환성 관리자 권한 설정 해제 실험

Steam 실행 파일의 호환성 설정에서 다음 항목을 해제했다.

- `관리자 권한으로 이 프로그램 실행` 비활성화
- 모든 사용자에 대한 동일한 관리자 권한 설정도 비활성화

이후 Steam 자체는 기존과 동일하게 관리자 권한으로 실행되도록 유지한 상태에서 다시 테스트했다.

그 결과 다음과 같은 차이를 확인했다.

| 실행 방식 | UAC 발생 | 실행된 게임의 권한 |
|---|---|---|
| Steam 클라이언트 내부에서 게임 실행 | 없음 | 관리자 권한 |
| `steam://rungameid/3308670` URI 호출 | 없음 | 관리자 권한 |
| Steam.exe에 `--applaunch` 인수 전달 | 없음 | 관리자 권한 |

즉, Steam 자체의 관리자 권한은 유지하면서 호환성 설정을 통한 강제 권한 상승만 제거하자, 기존에 UAC가 발생하던 외부 실행 방식에서도 UAC 확인 창이 더 이상 나타나지 않았다.

이 결과를 통해 문제의 원인은 Steam의 관리자 권한 실행 자체보다는 호환성 설정을 통한 실행 과정과 관련되어 있었을 가능성이 높다고 판단했다.

다만 이는 실험 결과에 기반한 원인 추정이며, Windows와 Steam의 내부 실행 처리 과정까지 확인한 것은 아니다.

### 6.3 최종 해결 방식

최종적으로 다음과 같이 실행 환경을 변경했다.

1. Steam 실행 파일의 호환성 관리자 권한 설정을 해제한다.
2. Steam 자체는 기존과 같이 관리자 권한으로 실행한다.
3. 게임 실행 요청은 기존 AHK 실행 스크립트의 URI 또는 실행 인수 전달 방식을 그대로 사용한다.
4. Steam 클라이언트에서 실행한 게임과 외부 실행 요청으로 실행한 게임 모두 관리자 권한으로 실행되는지 확인한다.

이 방식으로 기존 AHK 실행 코드와 게임별 실행 설정을 변경하지 않고도 UAC 반복 확인 문제를 해결할 수 있었다.

### 6.4 기존 해결 방식의 한계와 새로운 방식의 부작용

기존의 게임별 작업 스케줄러 등록 방식은 특정 게임만 관리자 권한으로 실행하도록 분리할 수 있다는 장점이 있었다.

그러나 Steam 게임이 추가될 때마다 작업 스케줄러 작업과 `.lnk` 바로가기를 별도로 생성해야 한다는 관리 부담이 있었다.

또한 실행 대상이 늘어날수록 예외 처리 목록과 유지보수 비용도 함께 증가한다.

이번에 적용한 방식은 Steam 자체를 관리자 권한으로 실행하는 구조이므로 게임별 예외 처리가 필요하지 않다는 장점이 있다.

반면 다음과 같은 부작용도 고려해야 한다.

- Steam 클라이언트 자체가 항상 관리자 권한으로 실행된다.
- Steam 클라이언트에서 실행하는 일반 게임도 관리자 권한으로 실행된다.
- 관리자 권한이 필요하지 않은 게임까지 높은 권한으로 실행되므로, 일반적인 실행 환경보다 권한 범위가 넓어진다.
- 게임의 안티치트, 외부 런처, 모드 및 기타 프로그램과의 호환성에 영향을 줄 가능성이 있다.
- 관리자 권한으로 실행되는 Steam 프로세스가 보안상 더 높은 권한을 가지므로, 해당 실행 환경을 신뢰할 수 있어야 한다.

따라서 모든 게임에 관리자 권한이 필요한 것은 아니며, Steam Overlay 사용과 권한 수준 일치를 위해 선택한 실행 환경이라는 점을 인지할 필요가 있다.

## 7. 최종 결론

이번 문제는 처음에는 특정 게임의 관리자 권한 및 Steam Overlay 호환성 문제로 시작했다.

이에 따라 게임별 작업 스케줄러 등록이라는 최소한의 예외 처리를 검토하고 적용했지만, 다른 Steam 게임에서도 동일한 UAC 문제가 발생할 수 있음을 확인하면서 기존 해결 방향을 재검토하게 되었다.

추가 실험을 통해 Steam 실행 파일의 호환성 관리자 권한 설정을 해제하고, Steam 자체는 별도로 관리자 권한으로 실행하는 방식에서 외부 URI 및 실행 인수 전달 시에도 UAC가 발생하지 않는다는 점을 확인했다.

최종적으로 게임별 작업 스케줄러 등록은 불필요해졌으며, 기존 AHK 실행 코드와 실행 구조도 변경하지 않았다.

**이번 사례의 최종 해결 방향은 게임별 예외 처리를 늘리는 것이 아니라, Steam의 실행 환경을 조정하여 기존 실행 경로를 그대로 사용할 수 있도록 하는 것이었다.**

이는 코드 구조를 복잡하게 개선하기 전에 실행 환경과 운영체제 설정을 먼저 검증하는 것이 더 근본적이고 간결한 해결책이 될 수 있음을 보여주는 사례다.
